# M2.6 — Security + Correctness Hardening — 2026-07-17

## What was implemented

M2.6 closes the release-blocking correctness and security gaps identified in
the post-M2.5 Architecture Health Review. The tenancy model, Auth.js session
boundary, service-layer ownership, and ADR-0001/0002/0003 decisions are
unchanged. What changed is the reliability of the mutation paths that already
existed:

1. **Promote-once** is enforced by a partial unique index and a fully
   transactional promotion path (23505 → 409 under race).
2. **Create-investigation** is a single transaction with a conditional
   alert-link update (single-winner under concurrency).
3. **Audit rows** co-commit with the mutations they describe via an optional
   transaction executor on `writeAudit` / `writeAuditRaw`.
4. **Login/register** have DB-backed rate limiting with exponential lockout
   and HTTP 429 + Retry-After.
5. **Seed wipe** deletes only `seed_%` rows, never operational uuidv7 data.
6. **Membership suspend** revokes Auth.js sessions for that org.
7. **List/lookup indexes** cover default keysets, entity_refs GIN, and the
   promote-once unique index.
8. **Security headers** (CSP, HSTS, XFO, nosniff, Referrer-Policy,
   Permissions-Policy) on every response.
9. **Investigation notes** append atomically (`jsonb ||`).
10. **Migrate CLI** fails fast without `DATABASE_URL` (no hardcoded fallback).

M2.6 is the **final M2-series milestone**. Remaining non-blocking findings
from the Architecture Health Review are assigned to M3 / M4 / M5 (see below).

## Architectural decisions

- **No new frameworks.** Rate limiting is Postgres-backed (`login_attempt`),
  not Redis — consistent with single-Node + PostgreSQL.
- **Database enforces promote-once.** Application checks remain for friendly
  409 messages; the partial unique index is the real invariant.
- **Audit executor is opt-in per call site** (`tx` argument defaults to global
  `db`) so the refactor could land incrementally without a big-bang rewrite.
- **Pragmatic CSP with `'unsafe-inline'`** accepted for M2.6; nonce-based CSP
  is documented debt (`docs/security/csp-nonce-debt.md`), not M2.7.
- **Seed ownership via `seed_%` PK prefix** — already produced by `sid()`;
  no new column required.
- **ADRs 0001–0003 unchanged.** Middleware stays cookie-presence-only.
